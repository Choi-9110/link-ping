# LinkPing 프로젝트 종합 점검 보고서
기준일: 2026-02-23

## 1) 한 줄 요약
현재 LinkPing은 **기능적으로는 MVP를 넘어선 v1 출시 직전 상태**이며, 수익 모델(광고 + 인앱결제 + 추천 루프)은 이미 코드에 반영되어 있습니다. 다만 **출시 전 반드시 막아야 할 보안/운영 이슈**가 존재합니다.

## 2) 프로젝트 전체 구조
- 플랫폼: Flutter (Android/iOS/Web/Mac/Windows/Linux)
- 핵심 스택: Riverpod, Hive, Firebase(Auth/Firestore), Google Mobile Ads, In-App Purchase
- 엔트리: `lib/main.dart`
- 데이터 구조:
  - 로컬: Hive (`links`, `settings`)
  - 클라우드: Firestore (`users`, `urlStats`, `notifications`, `sharedLinks`, `inquiries`, `modificationRequests`, `analytics`)

## 3) 현재 구현된 핵심 기능
- 링크 알림 생성/수정/삭제, 반복 요일, 종료일
- 다중 알림 시간(무료는 재화/광고, 프리미엄은 확장)
- 공유 링크 (`/s/{shareId}`) + 저장자 추적 + 고정 링크 수정 투표
- 소셜 인터랙션(응원/약올리기) + 5분 윈도우 제약
- 배지/스트릭 시스템
- 멀티언어 (en/ko/es/ja/zh)
- 광고
  - 배너, 네이티브, 리워드
- 결제
  - 월/연/평생 프리미엄 상품 ID 구조 있음
- 추천 시스템
  - 첫 추천: 보너스 링크 +1
  - 이후: 포링 +5 보상
- 관리자 문의 대시보드(웹 라우트 `/admin`)

## 4) 수익화 구조 점검
- 광고 수익
  - 무료 사용자에게 리스트 네이티브 광고, 하단 배너, 리워드 광고 노출
- 인앱결제 수익
  - 월/연/평생 상품 구조 완비
  - 프리미엄 혜택 UI/결제 플로우 구현
- 리퍼럴 성장
  - 초대코드/보상 체계 구현 (바이럴 루프 기반)

결론: 수익 모델 자체는 타당하며, **초기 PMF 탐색 단계에서 충분히 테스트 가능한 구조**입니다.

## 5) 출시 전 필수 수정 항목 (우선순위 높음)
- P0
  - 관리자 비밀번호가 클라이언트 코드에 하드코딩 (`admin_login_screen.dart`)
  - 인앱결제 검증이 클라이언트에서 `true` 처리 (`PurchaseService._verifyPurchase`)
- P1
  - 광고 위젯/일부 로직이 테스트 Ad Unit 사용 상태 (TODO 남아있음)
  - 설정 화면에 디버그 메뉴 노출 (`[DEBUG] 개발자 도구`)
  - 추천코드 조회가 전체 유저 스캔 방식 (유저 증가 시 비용/성능 문제)
- P2
  - 테스트 코드가 기본 카운터 템플릿 상태 (실제 앱 시나리오 미검증)

## 6) 사업성 평가 (해외 기준)
### 제품 적합성
- 강점
  - "저장만 하고 안 보는 링크" 문제를 정확히 겨냥
  - 습관/리텐션 요소(알림, 스트릭, 배지, 소셜) 결합
  - 글로벌 확장 준비(다국어 + 웹 랜딩)
- 리스크
  - 카테고리 경쟁이 강함(알림/투두/습관 앱 다수)
  - 차별화 포인트가 약해지면 CAC(획득비용) 상승 가능

### 비즈니스 모델 적합성
- Freemium + Ad + Subscription 혼합은 글로벌 모바일 앱에서 검증된 조합
- 현재 코드 기준으로는 **매출 실험을 바로 시작할 수 있는 상태**

## 7) 해외 매출 추정 (시나리오)
주의: 실제 DAU/잔존율/전환율 데이터가 없으므로, 아래는 모델링 추정치입니다.

### 가정
- 무료 유저 1명당 일 광고매출(배너+네이티브+리워드 합산) ARPDAU
  - 보수: $0.01
  - 기준: $0.02
  - 공격: $0.04
- 유료 전환율(월간 활성 기준)
  - 보수: 0.6%
  - 기준: 1.5%
  - 공격: 3.0%
- 유료 평균 월매출(혼합 상품 고려, 수수료 반영 후 단순화)
  - $4.5 / paid user / month

### 월 매출 추정
- 보수 시나리오 (MAU 10,000 가정)
  - 광고: 약 $2,500/월
  - 구독: 약 $270/월
  - 합계: **약 $2,770/월**
- 기준 시나리오 (MAU 50,000 가정)
  - 광고: 약 $15,000/월
  - 구독: 약 $3,375/월
  - 합계: **약 $18,375/월**
- 공격 시나리오 (MAU 200,000 가정)
  - 광고: 약 $96,000/월
  - 구독: 약 $27,000/월
  - 합계: **약 $123,000/월**

해석:
- 초기에는 광고 비중이 더 크고,
- PMF 이후에는 구독 비중이 빠르게 커지는 구조입니다.

## 8) 당장 실행할 30일 플랜
- 1주차: 보안/릴리즈 블로커 제거
  - 관리자 인증 서버화
  - 결제 영수증 서버 검증 도입
  - 테스트 광고 ID 전면 교체
  - DEBUG 메뉴 제거
- 2주차: 퍼널/수익 데이터 계측 고도화
  - 가입→첫 링크 생성→7일 유지→결제 전환 이벤트 정밀 추적
  - 국가/채널별 코호트 분리
- 3주차: 해외 시장 2개 우선 실험
  - 영어권 1개 + 아시아권 1개
  - 스토어 메시지/온보딩 카피 A/B
- 4주차: 가격/페이월 최적화
  - 연간 플랜 앵커링
  - 무료 한도/광고 강도 튜닝

## 9) 결론
- 기술 완성도: **중상 (출시 직전 수준)**
