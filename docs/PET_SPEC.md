# 링꾸 펫 (Linkku Pet) — 기능 설계 문서

> 다마고치형 마스코트 + 수집/꾸미기 BM 설계안
> 상태: **제안 v0.2 (논의용 초안)** · 2026-06-11
> 목적: V1 범위 확정 + 확률/천장/중복 수치 합의 + 외부 의견 수렴
> ※ 모든 수치는 **출시 후 데이터로 튜닝 전제의 시작값**입니다.
>
> **v0.2 변경:** 가챠를 **V2로 이동**(V1 제외 확정). V1은 "메인 1마리 다마고치 + 핑으로 펫 **확정 구매/교체**(가챠 아님)". 캐릭터 로스터 6종 확정(§2.5).
>
> ## ⏸️ v0.3 타이밍 결정 (2026-06-11) — 펫 *기능*은 출시 후로 전면 보류
> **앱 V1(첫 출시)에는 펫 다마고치 *기능*을 넣지 않는다.** 링꾸 마스코트는 **지금처럼 "귀엽게 보여주는" 정도만**(이미 리디자인으로 빈화면·온보딩 등에 적용됨). 먼저 **핵심을 검증한다:**
> 1. 사용자가 **링크 알람을 잘 쓰는가**(실천율)
> 2. **서로 찌르기/응원**(소셜)이 도는가
> 3. **핑이 잘 모이는가**
>
> 이 지표가 확인되면, 아래 펫 시스템(허기·감정·상점·에그·가챠·놀이터)을 **마케팅과 함께 단계적으로** 투입한다. → 그래서 이 문서의 "V1/V1.5/V2"는 **"출시 후 1·2·3단계" 로드맵**으로 읽으면 된다. (악마의 변호인 권고 = "핵심 리텐션 먼저 검증, 펫은 그다음"과 일치)
>
> 👉 **지금 할 일:** 검증 기간 동안 위 3개 지표(실천율·소셜·핑)를 계측해 두면, 펫 도입 후 효과를 비교할 베이스라인이 생긴다.

## 0. 한 장 요약

**"링꾸"는 두 가지 뜻을 동시에 가진다 — ① 링크를 꾸미다 ② 다마고치 캐릭터 '링꾸'.**
저장한 링크를 정해진 시간에 실천하면, 내 픽셀 펫 링꾸가 반응하고 자란다. 펫의 상태는 **내 루틴 실천의 거울**이다. 새 링꾸는 돈이나 광고가 아니라 **"알을 부화시켜" = 링크를 실천해서** 얻는다.

> 차별점 한 줄: **"내가 운동 안 하면 링꾸가 기운 없어져."** — 캐릭터 상태가 내 습관 실천과 직접 연동되는 습관앱은 한국에 아직 없다.

---

## 1. 핵심 디자인 원칙 (절대 규칙)

1. **혼내지 않는다.** 펫은 화내지 않는다. 측은하게 기죽을 뿐. 모든 대사의 주어는 **"나(링꾸)"**. 유저를 탓하는 문구는 단 한 줄도 없다.
2. **방치 일수 숫자 표시 금지.** "며칠째야" 같은 카운트다운 = 죄책감→부담→이탈. 시각적 시무룩함으로만 표현.
3. **수집/획득은 핵심 행동(링크 실천)과 묶는다.** 펫이 distraction이 아니라 습관을 *끌고 가는* 장치가 되도록.
4. **투명성으로 신뢰를 산다.** 확률·천장 전부 공개. (한국 유저는 가챠 조작 트라우마가 있어 투명성이 곧 차별점)
5. **펫 알림은 핵심 알림을 죽이지 않는다.** 채널 분리 + 하루 1회 캡.

## 2. 펫 상태 & 감정 시스템

### 허기(애착) 게이지
- 0~100. **링크 알림 실천 / 응원·찌르기 시 +채움.** 시간 경과로 천천히 감소.
- 24시간 무활동 → "배고픔/기죽음" 상태 진입 (화 ❌, 측은 ✅).

### 감정 스프라이트 (최소 5종 — 출시 필수)
| 상태 | 트리거 | 연출 |
|------|--------|------|
| 😊 신남 | 링크 실천 직후 | 폴짝 점프 + 반짝 |
| 🙂 평온 | 허기 양호 평시 | 기본 idle |
| 🍽️ 배고픔 | 허기 낮음 | 풀 죽어 앉음 |
| 🥺 기죽음 | 24h+ 무활동 | 작아지고 눈 퀭 |
| 🤩 감동 | 오랜만 복귀 | 울먹+반가움 |

> ⚠️ 슬라임은 표정 폭이 좁다. 이 5종이 **명확히 구분**되지 않으면 전략 전체가 무너진다 → 아트 1순위.

### 대사 예시 (반말 친근체, 혼내지 않기)
- **실천 직후:** "오늘도 해냈잖아. 나 너 좋아하는 거 알지?" / "야 이거 진짜 했어? 짱이다"
- **배고플 때:** "나 오늘 좀 힘들었어. 근데 괜찮아, 왔잖아." / "요즘 바빴구나... 나는 기다렸어."
- **오랜만 복귀:** "어 왔어? 나 조금 울 뻔했잖아. 됐어, 왔으면 됐지."

> 규칙: "기다렸어" 류 감정 대사는 **하루 1회만**. 반복되면 정(情)이 아니라 스팸이 된다.

## 2.5 캐릭터 로스터 (네이밍 = `[동물]꾸`)

브랜드 중의성 "링꾸"를 잇는 `~꾸` 작명. **링꾸가 디폴트**, 나머지는 핑으로 구매/교체.

| 캐릭터 | 동물 | 등급(제안) | 비고 |
|------|------|------|------|
| **링꾸** | 슬라임 | 기본 | 디폴트 지급(무료) |
| 꾸양이 | 고양이 | 일반 | |
| 백꾸 | 강아지(백구) | 일반 | 어르신 어필 |
| 레오파드개꾸 | 표범무늬 개 | 레어 | |
| 참새꾸 | 참새 | 일반 | |
| 붕꾸 | 붕어 | 레어 | |

> 각 캐릭터 = **감정 스프라이트 5종**(§2) 필요 → 6종 = 약 30스프라이트. 아트 부하 큼 → V1 출시 로스터 범위는 제작 속도에 맞춰 조절(예: 링꾸+3종 먼저, 나머지 패스트팔로우).
> 종 확장(시즌 추가 캐릭터)은 V2.

## 2.6 성격 시스템 (출시 후 / 포켓몬 성격 방식)

각 링ꓼ는 **고유 성격 1종**을 가진다(포켓몬 "성격"처럼). 같은 종이라도 성격이 달라 **말투/대사가 달라진다.**

- **기본 성격 ~30종**(예시 수치, 실제는 25~30 사이). 종 특성(예: 고양이의 도도함)이 그 위에 얹힌다.
- 성격 → **말투 변주**: 같은 "오늘도 해냈잖아"도 성격에 따라 다정/툴툴/새침/허세 등으로.
- 부화/획득 시 성격 랜덤 부여 → 수집·교환 동기(같은 종 다른 성격).
- 단계: 본격 구현은 **V2(펫 시스템)**. **도감 상세 화면엔 성격 영역을 V1 티저로 선반영**(현재 적용됨 — `linkku_dex_screen`).
> ⚠️ 비용: 성격별 대사 풀 = 콘텐츠 부하 큼. 핵심 성격 소수부터 시작, 점진 확장.

## 3. 획득 루프 — 에그 부화 (V1.5+, 무료)

새 링꾸는 **알(Egg)** 상태로 받고, **링크 실천으로 부화**시킨다. (= 수집욕이 습관을 끌고 가는 건강한 루프)

| 항목 | 시작값(제안) |
|------|------|
| 부화 조건 | **링크 알림 6회 실천** OR **3일 연속 실천** (먼저 도달하는 쪽) |
| 알 획득 | 도감 진행/이벤트/출석 보상 등으로 지급 (광고·결제 아님) |
| 부화 결과 | 희소도 확률표(§4)에 따라 랜덤 링ꓼ |
| 동시 보유 | 알은 1개씩 부화(멀티 부화는 V2) |

> 핵심: **에그 부화 = 메인 건강한 루프. 핑 가챠(§5) = 선택적 가속기.** 둘을 분리해 "공짜로 꾸준히 하면 모이고, 급하면 가챠" 두 트랙.

## 4. 컬렉션 · 도감 · 희소도

- **도감:** 미획득 링ꓼ는 **실루엣**으로 표시 → 수집 완성 욕구 자극.
- **희소 배지:** 보유 링ꓼ에 **"전체 유저 중 X명 보유"** 실시간 표기. 1,000명 이하 = `레어`, 100명 이하 = `슈퍼레어`.
- **희소도 등급 & 기본 확률:**

| 등급 | 약칭 | 확률 | 비고 |
|------|------|------|------|
| 커먼 | N | **70%** | 기본 슬라임 색·표정 변형 |
| 레어 | R | **23%** | 패턴/특수색 |
| 슈퍼레어 | SR | **6%** | 특수 종·이펙트 |
| 울트라레어 | UR | **1%** | 한정/시즌 픽업 |

> 합계 100%. 에그 부화·핑 가챠 **공통 확률표** 사용(투명성).

## 5. 핑 가챠 — 확률 / 천장 / 중복 규칙 (수치) · **V2 전용**

> 🔴 **가챠는 V2.** V1의 펫 구매는 **확정 구매(가챠 아님)** — §7-V1 참고. 아래는 V2 랜덤 뽑기 도입 시 규칙.

> ⚠️ **법적/정책 가드레일:** 랜덤 뽑기는 **스토어 정책상 확률 공시 의무** + 한국 확률 공시 의무화 흐름. **핑은 "광고로만 버는 소프트 재화"로 유지**(현금 직접 판매 금지) → 도박·연령 규제 회피. 현금 직접 판매 시 규제 강도 급상승.

### 5-1. 가챠 비용
| 구성 | 비용(핑) | 비고 |
|------|------|------|
| 단차(1회) | **100핑** | |
| 10연차 | **900핑** | 10% 할인 + 10연 내 R 이상 1개 보장 |

### 5-2. 천장(Pity) — 분노 방지, 신뢰 확보
| 천장 | 규칙 |
|------|------|
| **소프트 천장(SR)** | 누적 **30회** 동안 SR 이상 미획득 시, 다음 뽑기 **SR 이상 확정** |
| **하드 천장(UR/한정)** | 한정 픽업 이벤트에서 누적 **80회** 시 **픽업 UR 확정** |
| 천장 카운터 | 화면에 **항상 노출**(남은 횟수 표시) |

### 5-3. 중복(Duplicate) 처리 — "꽝 절대 금지"
이미 보유한 링ꓼ가 나오면 **"링꾸 조각"으로 전환**(천장 카운터는 유지).

| 중복 등급 | 전환 조각 |
|------|------|
| N | 5조각 |
| R | 15조각 |
| SR | 50조각 |
| UR | 200조각 |

- **조각 상점:** 조각으로 꾸미기 아이템 구매 또는 **원하는 링ꓼ 직접 교환**(조각 충분 시). → 중복도 "이득" 체감.

## 6. 핑 이코노미 밸런스 (수치)

핵심 원칙: **순발생(획득−소비)을 0~약음수로 유지.** 신규 소비처(sink) 추가 속도 ≥ 신규 획득처(source).

### 획득(Source) — 일일 비중 광고 ≫ 소셜 > 게임
| 소스 | 시작값(제안) | 일일 캡 |
|------|------|------|
| 광고(리워드) | 회당 +20핑 | 5~6회/일 → **~120핑/일** |
| 소셜(받은 응원/찌르기) | 1건 +2~3핑 | **30핑/일** |
| 미니게임(V2) | 1판 +5핑 | **20핑/일** (= 광고의 1/5 이하) |

> ⚠️ 게임 핑이 광고보다 후하면 **광고 볼 이유가 사라져 수익 잠식.** 게임은 반드시 보조.
> (참고: 현재 코드 `PoringService` 광고 일일한도=15회·쿨다운45초 → 위 제안에 맞게 재검토 필요)

### 소비(Sink)
| 소비처 | 가격(핑) | 비고 |
|------|------|------|
| 꾸미기 스킨/아이템 | 80~300 | 저축 페이스 조절용 |
| 핑 가챠 단차 | 100 | §5 |
| 링ꓼ 영입(가챠 누적) | ~500~1,500 | 3~7일 저축 = 1개 페이스 |
| 시즌 한정 스킨 | 변동 | 정기 sink로 핑 회수 |

## 7. 로드맵 — V1 / V1.5 / V2 (범위 선 긋기)

### 🟢 V1 — 다마고치 코어 + 펫 확정 구매 (메인 1마리)
- **화면엔 메인 링ꓼ 1마리만** 상주(다마고치 스타일). 기본 = **링꾸(디폴트, 무료 지급)**
- **허기 게이지 + 5종 감정 스프라이트 + 반응 말풍선(대사)**
- 링크 실천/응원·찌르기 → 허기 채움 / 24h 무활동 → 측은·기죽음
- 🛒 **펫 상점 = 핑으로 확정 구매/교체** (가챠 아님, 랜덤 아님 — 원하는 캐릭터를 정가로):
  - 로스터 §2.5 / 가격(제안): 일반 **500핑**, 레어 **1,200핑** · 링꾸는 무료
  - 산 펫 중 **1마리를 활성(메인)으로 선택·교체**
- **무료 기본 꾸미기 2~3종**
- 🛡️ 안전장치: 펫 알림 채널 분리+하루1회캡 / **"링크 실천율" 북극성 지표 계측**
- ❌ **V1 제외:** **가챠** · 여러 마리 동시 표시/놀이터 · 도감 · 에그 부화 · 미니게임
- 목적: *펫이 리텐션을 올리는지* 검증 + 확정 구매로 핑 sink 1개만 가볍게 검증

### 🟡 V1.5 — 수집 루프 (무료 획득 + 전시)
- **에그 부화**(6링크/3일) → 링ꓼ 무료 추가 획득(실천 기반)
- **도감**(미획득=실루엣) + **"X명만 보유" 희소 배지**
- **카톡 근황 공유 버튼** (바이럴)
- 꾸미기 스킨 확장

### 🔴 V2 — 경제 · 가챠 · 놀이터 · 종 확장
- 🎮 **다마고치 놀이터**: 산/모은 링ꓼ들이 **여러 마리 같이 뛰어노는 페이지** + 미니게임(핑 소량)
- **핑 가챠**(확률 공시 + 천장 + 중복 조각) §5 — 확정 구매와 별개의 *선택적* 랜덤 트랙
- **조각 상점**(핑 sink)
- **종 확장: 시즌 추가 캐릭터**(종마다 스프라이트 ×5 비용)
- **프리미엄 전용 링ꓼ/스킨**, 시즌 한정

> 단계 논리: V1=감정 검증 + **확정** 구매(가챠 도박성 없이 핑 sink 가볍게) → V1.5=핵심행동 연동 무료 수집 → V2=데이터 본 뒤 놀이터·가챠 경제. **도박성 가챠를 맨 마지막**에 둬서 리스크 분산.

## 8. 수익화 & 프리미엄 시너지

- 펫은 **광고 깔때기가 아니라 리텐션 엔진.** 광고 노출 증가는 *부산물*로만.
- **프리미엄(광고제거+무제한+클라우드백업) 전용 링ꓼ/스킨/색** = 감정적 결제 트리거.
- 프리미엄에 핑을 더 주지 말 것(광고제거와 충돌). 대신 **"광고 없이 즐기는 전용 콘텐츠"**로 가치 분리.
- 매몰비용 락인: 모은 컬렉션·스킨·도감 = 이탈 시 상실 → 재방문 고리.

## 9. 바이럴 & 한국 시장 훅

- **"내 링꾸 근황" 카톡 공유 버튼** — 앱 추천은 부담스러워도 "내 링꾸 자랑"은 자연 콘텐츠(띠부씰·이모티콘 문화).
- **희소 배지 + 도감** — 포켓몬 띠부씰식 수집 바이럴.
- **전연령 확장** — 어르신(아버지 세대)은 수집/가챠 **opt-in**, "펫 반응 + 링크 꾸미기"만으로 가치. 슬라임보다 **강아지/고양이**를 선호 → 종 확장이 흡수 채널.
- **첫 7일 첫 성취** — 신규 유저가 7일 내 "링ꓼ가 처음 크게 기뻐함"을 반드시 1회 경험하게(첫 실천 시 폴짝+감동 대사).

## 10. 리스크 & 미해결 질문 (악마의 변호인)

- **이코노미 밸런스는 기본값이 "망가짐".** 저보상→게임 안 함 / 고보상→광고 안 봄. 출시 후 A/B 튜닝 필수.
- **콘텐츠 트레드밀** — 스킨·대사·종은 무한 제작. 1인 리소스로 지속 가능한 *제작 속도*를 먼저 정할 것.
- **알림 스팸 = 핵심 알림 동반 사망**이 가장 치명. 채널 분리·캡은 협상 불가 규칙.
- **지표 오염** — 리텐션이 올라도 "습관 형성"인지 "펫 사료 주기"인지 구분 가능한 계측 설계가 V1 전제.
- **열린 질문:** ①에그 획득 경로(출석? 도감보상? 이벤트?) 구체화 ②종별 부화 조건 차등 둘지 ③조각 상점 직교환 비용 ④한정 픽업 운영 주기.

## 12. 홈 위젯 (출시 후 업데이트)

> 상태: **보류 — 첫 App Store 심사 통과 후 다음 업데이트로 진행** (네이티브 Xcode 타겟 추가 필요, 첫 심사 빌드 제외)
> 발의: 2026-06-11 (사용자 아이디어)

### 컨셉
홈 화면 위젯에 대표 펫 **링꾸**를 노출하고, 다가오는 알림 상태를 링꾸로 표현한다.
- 알림 0개 → 링꾸 기본(편안한 표정)
- 1~2개 다가옴 → 링꾸 위에 알림 벨 뱃지 `+N`
- 3~4개 → 링꾸 살짝 눌림 + 뱃지 쌓임
- 5개+ → 링꾸 **완전 짜부**(눌린) 스프라이트 + "헉" 표정 + 숫자
- 탭하면 앱 열기(딥링크)

### 기술 구조 (중요)
iOS 홈 위젯은 **Flutter로 못 그린다.** WidgetKit + SwiftUI로 만드는 **별도 익스포트 타겟**이 필요하고, Flutter 앱은 데이터만 공급한다.
- **데이터 다리:** App Group(공유 저장소) + `home_widget` 플러그인. 앱(Dart)이 다가오는/대기 알림 수를 `HomeWidget.saveWidgetData` → `HomeWidget.updateWidget`, 위젯(Swift)이 App Group `UserDefaults`에서 읽어 상태 결정.
- **스냅샷 기반** → 부드러운 실시간 애니메이션 불가. **상태별 이미지 전환(타임라인 엔트리)**으로 "짜부"를 단계 표현. 알림 예정 시각마다 엔트리를 만들어 시간이 흐르며 상태가 바뀌게 가능.
- **에셋:** 픽셀 링꾸 상태별 PNG(기본/살짝눌림/짜부 + 표정)를 위젯 타겟에 번들, 알림 수로 분기.

### 착수 체크리스트
1. `pubspec.yaml`에 `home_widget` 추가
2. Xcode에서 Widget Extension 타겟 생성
3. App Group 설정(앱+위젯 양쪽 entitlement, 동일 group id)
4. SwiftUI 위젯 뷰 + TimelineProvider 스켈레톤(상태→이미지 매핑)
5. 앱(Dart): 알림 스케줄 변동 시 pendingCount 저장 + updateWidget 호출 연결
6. **짜부 스프라이트(PNG)는 사용자 제공 예정**
7. (선택) Android 위젯 — `home_widget` 지원하나 별도 레이아웃 필요
